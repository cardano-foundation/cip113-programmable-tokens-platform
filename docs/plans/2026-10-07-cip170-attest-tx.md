# CIP-170 ATTEST_TX for attested mints — Implementation Plan

**Goal.** Attested mints (admin mint and initial CMTA mint) carry their CIP-170 attestation **inside the mint transaction** as `170: {t: "ATTEST_TX", i: <wallet AID>, v: {v: "1.1"}}`. The user's Veridian wallet anchors the CIP-170 v1.1 *transaction seal* — SAID of `{d, t: "cardano-tx-attest", n: <network magic>, txHash}` — and the separate label-170 child transaction is no longer built.

**Scope.** Backend `src/programmable-tokens-offchain-java`, frontend `src/programmable-tokens-frontend`, `docs/CIP170-MINT.md`. Branch `feat/tx-cip-170-attestation`. Result left staged, not committed.

**Decisions taken (user, 2026-10-07).** Replace the child-transaction profile (no new child builds). Apply to admin **and** initial mint. Veridian cannot verify the tx body before anchoring (CIP-170 v1.1 MUST for backend-built txs) → proceed and document the gap.

**Spec reference.** CIP-170 v1.1 text staged in `cardano/markdown/CIPs` (`CIP-0170/README.md` §Transaction attestations). Seal test vector: tx `4b1c…a2b3`, mainnet → `EOm0xWcPpijf-XF1T_cA8LcDm-99_MdNtZhCjPk4xC2_`; preprod (`n: 1`) → `EIe4UUF0iPy-cZCdXIO7o7FcJhcYqZh-Gdq_Ya2z-azj`.

**Global constraints.**
- No DB migration. `attestation_cbor` / `attestation_tx_hash` columns stay (nullable, unused for new intents).
- Records already `BUILT` with a child (admin intent or initial chain) stay **readable and recoverable** (a chain may be partly submitted). Only *new* builds use ATTEST_TX.
- **Profile discriminator** (exact): a row is ATTEST_TX iff its `documentJson` has keys exactly `d, t, n, txHash` in that order and `t == "cardano-tx-attest"`. A row whose document is exactly `{d, txHash}` is *retired*. Retired rows that are not `BUILT` are rejected **before any Veridian dispatch** in `prepare` (existingPrepare), `anchor`, `approve-and-build`, `finalize` and `build-chain`, with the distinct error code `RETIRED_ATTESTATION_PROFILE`; the frontend clears the stored request/intent IDs on that error (initial mint: points to Cancel, which releases reservations).
- KEL floor, remotesign transport, CIP-30 request auth, reservations and expiry logic are unchanged.
- Tests are changed only where they encode the child-transaction requirement being retired, or where test infrastructure must account for new classes (listed in Task 6, needs approval with this plan). Legacy-with-child fixtures are **kept** alongside new ones so recovery coverage is not lost.
- The legacy intent-document path (`requireAnchored`, `mints.attestation(i)` → `ATTEST 1.0`, TokenOperationsService:281) is untouched; ATTEST_TX uses a separate `mints.txAttestation(i)`.

---

## Summary

Today an attested mint is two transactions: the mint (no label 170) and a child that spends a plain mint output and carries `ATTEST` with `d = SAID{d, txHash}`. With ATTEST_TX the mint itself carries `170 {t: ATTEST_TX, i, v}` — known before the hash is computed — and the KEL seal is a purpose-tagged SAID over that mint's hash. Every mint handler already calls `MintAttestationMetadata.attach(tx, request.attestation())`, so the metadata change is centralised; the draft builder starts passing the wallet AID in. The initial-mint chain loses its child: the stake-certificate transactions chain directly from the registration's reserved fee-payer output. Validators flip from "mint must not contain 170" to "mint must contain exactly this ATTEST_TX". Frontend admin mint signs and submits one transaction instead of two.

## Diagram — before / after

| Step | Before (child profile) | After (ATTEST_TX) |
|---|---|---|
| Build mint draft | no label 170 | label 170 `{t: ATTEST_TX, i: walletAid, v: 1.1}` |
| Seal sent to Veridian | `{d, txHash}` | `{d, t: "cardano-tx-attest", n: <magic>, txHash}` |
| After anchor | build child tx spending mint output, `ATTEST {i, d, s}` | nothing to build; mint CBOR is final |
| Admin frontend signs | `signTxs([mint, child])` | `signTx(mint)` (partial) → submit one |
| Initial chain | … → registration → **child** → regTransferLogic → regThirdParty | … → registration → regTransferLogic → regThirdParty |
| Validator on mint | rejects label 170 | requires exact ATTEST_TX, no `d`/`s` |

## Acceptance criteria

1. `TxAttestationSealTest` reproduces both CIP-170 v1.1 test vectors (mainnet `EOm0x…`, preprod `EIe4U…`) and the exact preimage.
2. Admin attested mint: `prepare` returns a frozen mint CBOR whose label 170 is exactly `{t: ATTEST_TX, i: walletAid, v: {v: "1.1"}}` and whose digest = seal SAID over its own hash (`MintAttestationServiceTest`); `build-chain` returns that same CBOR with null attestation fields; no child is built.

4. Validators reject: missing/extra fields in ATTEST_TX, wrong AID, `d`/`s` present, wrong version, label 170 on any other chain tx.
5. Retired-profile row (not BUILT) is rejected in prepare/anchor/approve-and-build/finalize/build-chain **without** a transport call (mock verifies `sendAndWait` never invoked); legacy BUILT admin row still returns its stored child; legacy BUILT initial chain still recovers (kept legacy fixture).

### Task 1 — Seal payload is the CIP-170 v1.1 transaction seal (check: `TxAttestationSealTest`)
- New `TxAttestationSeal.signed(txHash, magic)` / `digest(...)` / `preimage(...)` / `isSealDocument(json)` with `LinkedHashMap` order `d, t, n, txHash`, `n` as integer.
- `TxAttestationSeal.magic(networkName)`: explicit map mainnet→764824073, preprod→1, preview→2, devnet→42; anything else throws (no mainnet fallback).
- `MintTxHashPayload` stays to recognise retired `{d, txHash}` documents. Test lives in `org.cardanofoundation.cip113.offline` (auto-allowlisted in ciTest).

### Task 2 — Mints embed ATTEST_TX metadata (check: `MintAttestationMetadataTest` new, validator tests)
- `Cip170AttestationData` gains optional `type` (`null`/`ATTEST` | `ATTEST_TX`) with `Cip170AttestationData.attestTx(aid)`; a secondary 4-arg constructor keeps existing call sites as `ATTEST`.

- `TokenOperationsService.buildMintDraft(fields, attestation)` passes it to the handler request.

### Task 3 — Admin mint is one transaction (check: `MintAttestationServiceTest`)
- `prepare`: resolve session (already done) → draft with `attestTx(session.aid)` → `validateMint(cbor, fields, aid, sealDigest = null, magic)` (null digest skips only the seal comparison; the exact ATTEST_TX for `aid` is always required) → seal over draft hash → `transport.prepareExchange`. Drop the 5-ADA child funding precondition.
- Retired-profile guard (constraint above) in `existingPrepare`, `anchor`, `buildChain` before any transport call.
- `buildChain`: after the existing anchor/floor/expiry checks and `validateMint(..., aid, sealDigest, magic)`, mark BUILT with the frozen CBOR (store `publishBuild`); return `Chain(mintCbor, null, mintHash, null)`. `chain()` accepts a null child for ATTEST_TX rows; legacy BUILT rows keep returning their stored child.

### Task 4 — Initial mint chain has no child (check: `InitialMintTransactionValidatorTest`, `InitialMintAttestationStoreTest`)

Legacy BUILT chains are never re-validated (recovery reads stored JSON), so no legacy branch is needed.
